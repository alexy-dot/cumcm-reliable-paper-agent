# Artifact contracts

Use one run directory as the durable state boundary. Keep every JSON file valid UTF-8 and preserve `run_id` across all files.

## `source_manifest.json`

Generated by `init`. Do not edit source hashes manually. Each source records its original filename, frozen relative path, byte size, role, and SHA-256. Do not store an absolute user path in a sealed package.

## `source_audit.json`

Generated by `init` or regenerated with `inspect` only while the run remains at `READING`. Require exactly one audit row per frozen source and bind each row to the source SHA-256 and frozen relative path.

- For text-like problem files, require a hashed extracted-text artifact.
- For CSV/TSV files, record encoding, delimiter, row and column counts, ragged rows, blank cells, header candidate, bounded preview and full `profile`.
- For DOCX files, record paragraph and character counts plus extracted text.
- For XLSX/XLSM files, scan each sheet to EOF. Record declared dimensions separately from `actual_total_rows` and `actual_data_rows`. Each sheet has a full `profile`, formula/cache/error counts, unresolved shared strings, merged ranges and observed coordinates. Keep six preview rows for orientation only.
- For unsupported formats, keep `parse_status: MANUAL_REQUIRED` until `manual_review.completed` is true and `manual_review.evidence` is non-empty.

`profile` excludes the first stored row as a header candidate; confirm that convention against the source. Missing counts use stored data rows and observed columns, including omitted cells; absent worksheet row numbers are not synthesized. Duplicates use hashes of exact decoded cell text, excluding empty cells; they are not entity duplicates and do not equate `1` with `1.0`. Numeric statistics use finite float-parsable values; nonfinite and text counts remain separate. Dates and identifiers need semantic interpretation. Means use an incremental average, not exact decimal arithmetic. Row hashes use memory proportional to unique rows in one sheet.

`scan_complete` is required for tabular source gates. Unreadable tails and unresolved shared strings block. Missing data, duplicates, formula caches and other findings are reported without modifying the input: decide their treatment in the existing problem/assumption ledgers, not an extra approval form. Cached formulas are not recalculated. A successful scan does not establish model validity.

## `problem_contract.json`

For each question require:

- `id`: stable question ID such as `Q1`.
- `source_locator`: page, paragraph, table, or exact wording locator.
- `objective`: computable target or decision rule.
- `inputs`, `outputs`, `decision_variables`: explicit non-empty lists.
- `hard_constraints`: include explicit “none beyond data domain” when genuinely absent.
- `units`: internal and display units.
- `ambiguities`: record “none found after review” when empty in substance.
- `termination_condition`: mathematical, algorithmic, or finite-enumeration stop condition.

## `assumption_ledger.json`

Each item requires `id`, `text`, `evidence`, `impact`, and `status`. Use statuses such as `ACTIVE`, `SENSITIVITY_REQUIRED`, or `REJECTED`. Never use an assumption to overwrite an explicit problem fact.

## `model_plan.json`

Create exactly one row per question with:

- `baseline`;
- `observed_bottleneck`;
- `primary_method`;
- `independent_method` different from the primary method;
- `validation_plan` covering constraints, anchors, residuals, sensitivity, and counterexamples as applicable.
- `agreement_tolerance`: finite, nonnegative `atol` and `rtol`, plus a concrete `reason`; frozen before comparing results.

## `results.json`

Create exactly one row per question. Use status `HYPOTHESIS`, `PROVISIONAL`, `VERIFIED`, or `REJECTED`. Each `headline_results` item requires:

- globally unique `id`;
- `label`, numeric or categorical `value`, and `unit`;
- `source_artifact`: a JSON object artifact relative to the run directory;
- `source_pointer`: JSON Pointer to its exact value, e.g. `/slope` or `/estimates/0/value`;
- its own result `status`.

Record `constraints` as explicit checks with `id`, `passed`, and `evidence`. If no mathematical constraint exists, include a passed applicability check explaining the data-domain boundary.

Headline `value` must equal the referenced machine value before stage freezing, including array contents. Use finite numbers, nonempty categorical strings or nonempty arrays of these; booleans, null and nonfinite numbers are rejected. Keep full precision in the ledger and round only for display. For CSV or other solver outputs, export authoritative headline values to a JSON object. Older runs lacking `source_pointer` fail until migrated in a new version.

## `verification_report.json`

Use `p0_checks` with boolean `passed`. Use `p1_checks` with `verdict` in `PASS`, `WARN`, or `FAIL`. A `WARN` must include `allowed_language`; optionally add `question_ids` and `forbidden_terms`.

For each question record:

- `id`;
- exact `independent_method` copied from `model_plan.json`;
- at least two `anchors`, including one hard anchor type;
- `independent_agreement` with boolean `passed`, tolerance, and evidence;
- Within `independent_agreement`, `comparisons` must cover each headline result exactly once: `result_id`, `reference_artifact` (separate JSON output), `reference_pointer` (JSON Pointer).
- counterexamples and sensitivity results where relevant.

The engine recomputes each comparison from both files, element by element. Numeric agreement requires `abs(primary-reference) <= atol + rtol*abs(reference)`; categorical strings require equality. A declared pass cannot override disagreement. Reference artifacts are included in P1 fingerprints. Separate files alone do not prove different mathematical methods; review the implementations and the tolerance justification.

## `claim_ledger.json`

Set `paper_artifact` to the final paper relative path and `paper_source_artifact` to a UTF-8 Markdown, LaTeX, or text source. Every claim requires `id`, `question_id`, `text`, non-empty `result_ids`, `paper_locator`, an exact `paper_excerpt` found in the source, and `status: VERIFIED`.

Do not link a claim to a provisional or rejected result. Do not use a strong term forbidden by an applicable P1 warning.

All artifact paths must be relative to the run directory. Reject absolute paths and `..` traversal.

## `signoff_ledger.json`

Keep the six generated sign-off rows and use `status: APPROVED` only after a human reviewer checks the cited evidence. Run `signoffs` immediately before review and copy the displayed `expected_scope_sha256` into `scope_sha256`. Require `reviewer_type: human`, a reviewer name, concrete evidence, and an approval timestamp. A scope mismatch invalidates approval. An agent must not approve or fabricate a human sign-off.

These fields record a declaration; the local JSON ledger does not authenticate the reviewer. Reuse explicit approval already given for the same reviewed content rather than requesting it again.

- `S1-INTERPRETATION`: central interpretation, required at `READING`.
- `S2-ASSUMPTIONS-MODEL`: assumptions and model choice, required at `MODEL_DRAFT`.
- `S3-KEY-REPRODUCTION`: one important numerical reproduction, required at `P1_PASS`.
- `S4-FINAL-FEASIBILITY`: final constraint feasibility, required at `P1_PASS`.
- `S5-ABSTRACT-HEADLINES`: abstract numbers and strong wording, required at `PAPER_LINKED`.
- `S6-RULES-AI-DECLARATION`: current rules and AI-use declaration, required at `PAPER_LINKED`.

## Optional `paper/document.json` renderer

Install `scripts/requirements-paper.txt` for PDF output. Use a JSON object with `title`, optional `status_note`, and `sections`. Each section has `title`, optional `page_break_before`, and `blocks`: a block contains `text`, a rectangular `table` (first row is its header), a run-relative `image` with optional `caption`/`width_cm`, or an `equation` containing TeX mathematics. Inline mathematics uses `$...$`. The renderer creates `paper/main.md`, `paper/main.pdf` and `paper/render_report.json` from the same content.

Mathematical documents automatically route through `render_latex.py` and retain editable `paper/main.tex`. Install Tectonic/XeLaTeX or supply `--latex-compiler /path/to/tectonic`; `--cache-dir` selects the TeX cache. On macOS, the defaults are Songti SC body, Heiti SC headings and Times New Roman Latin text; other platforms use Fandol Chinese fonts. Missing-glyph errors fail compilation. Prose-only documents can use the lightweight renderer and `--font` for an embeddable serif CJK TrueType font. Inspect actual pages before recording visual acceptance. Rendering does not approve the paper, validate its science, or apply every official formatting requirement.

The TeX render receipt is `PENDING` until compilation succeeds, then `COMPILED` with both document-source and PDF SHA-256. A failed compile may leave an old PDF on disk; its presence cannot establish that the latest source was rendered. The furnace workflow checks these hashes before linking claims.

`paper_structure.py` reads a supplied `--contract` (or discovers `problem_contract.json` beside the parent of the paper directory). For a standalone PDF use an explicit `--question-count`; there is no implicit four-question default. It maps contract questions in their listed order to numbered 问题一/问题1 headings inside the analysis and solution sections, accepting common chapter-numbering variations. It reports missing IDs, unknown labels and page locations, and hashes both the PDF and contract. Unrecognized/combined section layouts require editorial review rather than a guessed pass. This is coverage of section labels, not proof that nested outputs or answers are complete.

The renderer uses A4 and 2.5cm body margins; this is only one part of the official format. `submission-check` inspects actual PDF text/image bounds, summary markers, heading order, ZIP inventory, appendix/source correspondence, declared AI usage and known identity terms. Provide `--paper` and `--support` as run-relative paths; `--report artifacts/submission_report.json` optionally saves the result. Omitted support is accepted only for an explicit no-support statement without required AI details; `--no-code` additionally requires the matching no-program statement.

The source-bound rules live in [submission-2026.json](submission-2026.json), including official URLs, raw-source hashes and verification date. Unsupported years never inherit another year's rules. `FAIL` reports a failed named check, `UNAVAILABLE` indicates an uninspected format/resource, and `REVIEW_REQUIRED` indicates unresolved evidence. Supplied identity terms are redacted from reports. SHA-256/MD5 fingerprints describe inspected files, not proof that codes were submitted to the official platform. RAR and Word are officially allowed but are not automated by this PDF/ZIP checker. Unknown identities, graphics, regional rules, actual AI contribution review and substantive correctness remain manual responsibilities; `submission_ready` stays false.

## `state.json` and `artifact_manifest.json`

Modify `state.json` only through the CLI. Each `advance` stores a SHA-256 fingerprint of the completed stage's semantic inputs and result artifacts. Any later drift fails `CORE-UPSTREAM-FREEZE`. Seal from `PAPER_LINKED`; the seal command writes final validation, changes state to `VERIFIED`, and hashes every run artifact except the manifest itself.

## Support ZIP and complete source appendix

Run `python3 scripts/package_support.py RUN --selection selection.json --output artifacts/package-v1`.
The selection is an object with `files`: each row has a run-relative `source`, relative `archive_path`, and `role` (`code`, `data`, or `document`). Select all necessary files explicitly; the packager does not infer dependency completeness.

The new output directory contains a deterministic `support.zip`, `appendix.json` and `package_receipt.json`. The ZIP includes original file bytes and their hashes; the appendix includes the complete UTF-8 source of every `code` file. Append the generated section to the paper document's `sections` before rendering. `code` blocks have `filename` and literal `code` text; they automatically use TeX's verbatim-file reader and wrap across lines/pages without interpreting code as TeX. These are source listings, not images or summaries.

Do not edit the ZIP and appendix separately. Regenerate a new package version if a source changes, and rerun from a clean extraction to establish reproducibility. AI-use details and human verification must remain truthful; packaging sets `submission_ready: false` and does not fabricate them.
